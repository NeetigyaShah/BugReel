# Three-chunk split loading to honor the <4KB sensor claim

One Rollup/tsup build produces both the CDN IIFE/UMD bundle and the ESM/CJS npm package, split into three chunks: (1) `bugreel-loader` (<3.5KB gzipped) — the click/input/route listeners and their observation windows, the stage-1 privacy gate, the worker transport with its `preWorkerQueue`, and the hotkey trigger; (2) the worker + Story Engine, instantiated lazily after first paint; (3) the Shadow DOM modal, dynamically imported only when a report is triggered. The "<4KB sensor" claim in all positioning refers to Chunk 1 only — most sessions never download Chunk 3 at all. Script-tag installs auto-init via `data-*` attributes; npm installs call `initBugReel({...})`.

**Amendment (T03/T05 integration):** the fully featured stage-1 firewall pushed the loader to 4.72KB, so the heavier capture paths moved out of chunk 1 into a lazy `capture` chunk loaded right after the loader (sibling classic `<script>` on the CDN, a static import on npm): the fetch/XHR/console/error wrappers, the opt-in shake trigger, the floating pill, and the descriptive target enrichment (selector, label, heading, rect). Chunk 1 keeps only the synchronous privacy decision.

Trade-off: on the CDN path there is a short window (typically tens of milliseconds) after the loader runs in which network, console and error events are not yet captured, and clicks in that window carry a bare `tag#id` target instead of the enriched one. Nothing in that window can be backfilled, so installs that cannot tolerate it should use the npm entry, which installs capture synchronously.
